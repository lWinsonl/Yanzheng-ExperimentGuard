## 研证可以帮你做什么

学生提出研究主张，上传实验计划、代码或运行记录。研证提取带原文位置的候选事实，经用户确认后执行审查，列出问题依据、受影响的主张、缺失证据和修改建议。

它面向本科选题、课程项目和科研入门中的实验训练，帮助学生检查“我做的实验，能支持我写下的结论吗？”。当前规则覆盖**数据与模型实验**、**算法与系统性能实验**。

<table>
  <tr>
    <td width="33%" valign="top">
      <strong>原文可追溯</strong><br /><br />
      每条候选事实保留材料片段和字符位置，审查发现可以回到原文核对。
    </td>
    <td width="33%" valign="top">
      <strong>事实由人确认</strong><br /><br />
      用户确认、纠正或拒绝候选事实，普通规则审查只使用确认后的事实。
    </td>
    <td width="33%" valign="top">
      <strong>修改后再复查</strong><br /><br />
      补充材料后重新审查，对照仍触发和不再触发的问题，保留修改理由。
    </td>
  </tr>
</table>

## 三个差异化能力

除了基础的证据链审查，研证还提供三个同类工具少有的能力：

<table>
  <tr>
    <td width="33%" valign="top">
      <strong>主张—证据图与反证检索</strong><br /><br />
      把每条研究主张拆成子主张，用确定性规则建立子主张与证据的连接，再由模型补充候选边（附原文引用，防幻觉）。检索反证时区分"找到反证 / 缺失反证 / 未知"三态，而不是只报"不支持"。
    </td>
    <td width="33%" valign="top">
      <strong>基于预期信息价值的主动追问</strong><br /><br />
      不是列一张固定的问题清单，而是为每个候选追问计算预期信息价值（EIV = 严重度 × 不确定性 × 改变概率 ÷ 回答成本），按"回答哪个问题最可能改变审查结论"排序，并解释为何先问这个。学生回答后自动重算审查，追踪发现是否因此消除或降级。
    </td>
    <td width="33%" valign="top">
      <strong>版本差异复审与学习迁移评估</strong><br /><br />
      修改实验后，按稳定身份（规则 + 主张 + 证据范围 + 问题类别）配对前后发现，判定"已解决 / 缓解 / 仍存在 / 新问题 / 证据不足"五态，并将学生声称的修改理由与事实层面的实际变化对照。再生成一个<strong>不同表面情境、同一方法要点</strong>的迁移题，按推理过程四维评分，验证学生是否真正学会了方法。
    </td>
  </tr>
</table>

## 一个具体例子

> **研究主张：** 模型 A 比基线 B 更能预测新设备的故障，且更稳定。

| 对照对象 | 材料中的信息 | 需要核实的问题 |
| :--- | :--- | :--- |
| **主张** | 目标是预测训练时未见过的新设备 | 测试设备是否确实独立于训练设备？ |
| **计划** | 按设备划分训练集与测试集 | 执行中是否保留了这个划分约束？ |
| **执行** | 出现 `train_test_split(X, y, ...)` | 输入是记录还是设备编号？两侧设备编号是否重叠？ |

研证把这些信息及其出处放在一起，提示用户核对真实划分过程，再决定补充证据、修改实验或收窄结论。**引用确实存在，不等于推断一定成立。**

## 五步完成一次审查

| 步骤 | 你来做 | 研证来做 |
| :--- | :--- | :--- |
| **01 确定范围** | 选择实验类型，逐条填写研究主张 | 分析主张需要哪些实验设计依据 |
| **02 收集材料** | 上传文件或粘贴内容，标记计划 / 执行 | 解析材料、提取候选事实、提示材料缺口 |
| **03 确认事实** | 查看原文，确认、纠正或拒绝 | 保存状态，筛选普通规则审查可用的事实 |
| **04 审查报告** | 查看发现、证据和修改建议；按 EIV 排序回答追问 | 区分明确矛盾、潜在风险、信息不足；提供主张—证据图、模型复核与追问排序 |
| **05 修改复查** | 补充材料并填写修改理由；作答迁移题 | 重新审查并按稳定身份对比前后报告（五态判定 + 理由对照）；生成迁移题并按推理过程四维评分 |

可加载示例主张和示例材料体验流程。报告页提供**主张—证据图**（可校准子主张-证据连接与反证检索）、**EIV 主动追问**（按预期信息价值排序，回答后追踪发现变化）、**版本差异复审**（五态判定 + 修改理由对照 + 人工标签）和**迁移题测验**（不同情境同方法要点，四维推理评分）；报告支持 **Markdown 导出**，也可生成教学小案例供学生练习判断。

收集材料时支持“补充”或“替换旧版本”。替换会清除同角色的旧材料及关联事实，并重置主张—证据图、追问与迁移数据；**历史报告会被保留**，供版本差异复审对比前后发现。当前尚不保留可回退的材料版本快照。

## 从材料到发现的证据链

```mermaid
flowchart LR
    A[计划与执行材料] --> B[解析与事实提取]
    B --> C[原文片段与位置校验]
    C --> D{用户核对}
    D -->|确认或纠正| E[规则审查]
    D -->|拒绝| F[不进入规则审查]
    E --> G[发现 · 依据 · 建议]
    G --> I[主张-证据图与反证检索]
    G --> J[EIV 主动追问]
    J -->|学生回答| E
    G --> H[补充材料与版本差异复审]
    H --> B
    H --> K[迁移题 · 推理过程评分]
    style D fill:#eaf3ff,stroke:#1765cc,color:#122447
    style E fill:#eaf7f6,stroke:#11858b,color:#122447
    style G fill:#fff6e6,stroke:#b67a18,color:#122447
```

普通规则审查与模型辅助分析有各自的输入路径。深度复核会直接读取部分材料文本（长文档截取前段并在提示中标注未提供部分），其输出独立于普通规则报告；具体处理方式见[架构说明](docs/architecture.md)。

## 本地启动

需要 **Python 3.10+**、**Node.js 22.12+** 和 npm。以下命令从仓库根目录开始执行。

### 1. 获取项目

```bash
git clone https://github.com/lWinsonl/Yanzheng-ExperimentGuard.git
cd Yanzheng-ExperimentGuard
```

### 2. 启动后端

```bash
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8002 --reload
```

### 3. 启动前端

另开一个终端，从仓库根目录执行：

```bash
cd frontend
npm ci
npm run dev
```

| 入口 | 本地地址 |
| :--- | :--- |
| 前端界面 | [localhost:5173](http://localhost:5173) |
| 后端接口文档 | [127.0.0.1:8002/docs](http://127.0.0.1:8002/docs) |

前端默认将 `/api` 转发至 `127.0.0.1:8002`。打开页面后，点击**加载示例**创建会话，再在收集材料页分别加载并提交示例计划与执行材料。

<details>
<summary><strong>可选：接入模型与启用 PDF 解析</strong></summary>

参考 [`backend/.env.example`](backend/.env.example)，在 `backend/.env` 中设置：

```dotenv
LLM_API_KEY=你的密钥
LLM_BASE_URL=兼容服务的接口地址
LLM_MODEL=服务提供的模型名称
```

密钥仅放在后端配置中，不要提交到仓库。

基础流程可在无模型配置时运行：方向分析、材料缺口、追问和教学案例会采用启发式或预设内容，深度复核会明确提示未接入模型。配置兼容模型服务后，模型事实提取会尝试补充规则未覆盖的事实，并校验原文引用与去重；模型调用失败时回退到规则提取，深度复核在偶发超时后会自动重试一次。

PDF 文本提取需要另行安装可选依赖：

```bash
python -m pip install pypdf
```

## 支持的材料

| 材料 | 当前处理方式 |
| :--- | :--- |
| 文本、Markdown、代码、配置、CSV、日志 | 按文本解析并建立字符位置索引 |
| Jupyter Notebook | 提取各单元格源码，再建立位置索引 |
| 含文本层的 PDF | 安装 `pypdf` 后提取文本，无法读取的内容提示缺口 |
| DOCX、XLSX、扫描件 OCR | 暂未实现对应解析器 |

文件选择框目前未限制扩展名，能选中文件不代表能正确解析。材料会发送到 Python 后端并写入 `data/`；调用模型分析时，相关材料或事实也可能发送到所配置的模型服务。

## 当前实现与边界

| 模块 | 已有能力 | 仍需完善 |
| :--- | :--- | :--- |
| 数据与模型规则 | 划分一致性、泛化范围、重复运行、基线、指标 | 关键词规则的解释强度与执行证据要求 |
| 算法与系统规则 | 基线、性能指标、稳定性重复运行、材料完整性 | 更广泛的系统实验情境与实际案例验证 |
| 主张—证据图 | 确定性规则构建子主张-证据连接；模型补充候选边并附原文引用（防幻觉）；反证检索区分找到 / 缺失 / 未知三态 | 候选边质量依赖模型；图结构未持久化到导出报告 |
| 主动追问 | EIV 可解释评分排序（严重度 × 不确定性 × 改变概率 ÷ 成本）；回答后重算审查并追踪发现变化；统计完成率与变化率 | EIV 因子权重为手工设定，未经大规模数据校准 |
| 版本差异复审 | 稳定身份（规则 + 主张 + 证据范围 + 问题类别哈希）配对前后发现；五态判定与理由；修改理由与事实变化对照；人工标签计算已解决精确率 | 证据不足态的判定依赖事实提取覆盖率 |
| 学习迁移评估 | 生成不同表面情境、同一方法要点的迁移题；四维推理评分（识别问题 / 解释原因 / 提出修改 / 推理质量）；启发式降级保证无模型可用 | 迁移题情境多样性受预设模板限制 |
| 模型辅助分析 | 事实提取、方向、缺口、追问、深度复核、教学案例、候选边、迁移题生成与评分；复核区分调用与解析失败并自动重试 | 复核引用未完整绑定声明文件；引用失败时仍可能保留无引用的建议 |
| 会话保存 | JSON 原子写入（防并发损坏）与启动恢复，前端会话记忆、历史入口；追问、版本差异、迁移数据均持久化 | 写入失败时的用户可见反馈 |
| 修改复查 | 按稳定身份配对前后报告（五态判定）；材料替换保留历史报告供对比，清除图 / 追问 / 差异数据 | 替换后的材料版本快照保留 |
| 报告导出 | 导出规则发现、证据、建议、追问，以及当前页面的模型复核状态、覆盖范围和结果 | 版本差异与迁移结果尚未纳入导出 |

当前为科研训练原型。未发现问题不能解读为实验已全面通过审查；已有免费演示部署配置，但尚无用户隔离和上传配额。更详细的代码分析见[架构与待完善项](docs/architecture.md)。

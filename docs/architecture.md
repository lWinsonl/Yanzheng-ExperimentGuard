# 研证代码架构与实现边界

本文对应当前 React + FastAPI 实现，依据源码说明已有行为，不把注释中的目标当作已完成能力。

## 前端工作流

`App.tsx` 使用组件状态切换 setup → upload → facts → report → recheck，保存当前会话。`SetupPage` 创建会话后自动调用方向分析；`UploadPage` 上传文件或提交文本并刷新材料缺口；`FactConfirmPage` 提供确认、纠正、拒绝；`ReportPage` 运行规则审查、生成追问并提供深度复核及教学案例；`RecheckPage` 调用复查接口。

上传入口在创建会话后的“收集材料”页，文件通过 multipart/form-data 发给后端。前端 API 固定使用 `/api`，本地 Vite 代理到 8002 端口。生产单容器由 FastAPI 同源托管前端构建产物与 API；云端演示配置见[部署说明](deployment.md)。

## 证据链

1. `EvidenceChainService` 根据扩展名选择解析器，得到 `ParsedDocument`。
2. `RuleExtractor` 用正则提取划分、指标、基线、重复次数等候选事实。
3. 每条事实携带 `SourceSpan(material_id, start_char, end_char, snippet)`。
4. `_add_verified` 校验引用与文档切片完全一致后保存为待确认状态。
5. 用户确认或纠正后，事实进入 `usable_facts()`；拒绝或未确认的事实不进入普通规则审查。
6. `Finding` 通过 `EvidenceRef` 指向事实及原文，并关联主张、缺失证据、修改建议。

这里验证的是引用存在性，不是事实解释的真实性。纠正后的事实值仍关联原来的原文片段，系统未验证改写后的值是否由该片段支持。

## 规则与模型的分工

规则注册器包含五个 `data_model` 规则：划分一致性、泛化范围、重复运行、基线、评价指标；以及四个 `algorithm_system` 规则：基线对比、性能指标、稳定性重复运行、计划与执行材料完整性。规则仍依赖提取事实与关键词，未触发发现不等于证明实验正确。

`AgentService` 另外提供方向分析、材料缺口、追问、深度复核与教学案例。客户端使用服务端配置的兼容 Chat Completions 接口。方向分析、缺口、追问和案例可以回退到启发式结果；深度复核无模型时返回空列表。

`LlmExtractor._call_llm()` 已连接模型客户端。模型事实需通过原文逐字引用校验，并与规则事实按归一化值及原文范围去重。无模型配置或调用失败时回退到规则结果。

深度复核直接读取材料文本，绕过普通规则审查的“已确认事实”路径；每份材料最多取前 2000 字，总量受 8000 字预算限制。输出单独返回，不写入后端普通报告和复查记录，但当前页面的复核结果可加入 Markdown 导出。

## 存储与复查

`DataStore` 在内存中保存会话聚合，变动时写入 JSON，启动时恢复会话、材料、事实、报告与复查结果。损坏文件会被跳过，写文件失败仍会被忽略。前端通过 localStorage 保存当前会话和步骤，恢复时向后端核验会话，并在首页提供历史会话入口。

复查重新运行规则，并按 `rule_id` 对比上一份报告。它不保存独立的材料版本快照，不会自动废弃旧执行材料。同一规则出现多条发现时，目前无法逐条准确配对。

## 代码阅读中发现的待完善项

- **审查覆盖**：系统性能类型已有四类规则，但覆盖范围仍有限，未发现问题不能解读为全面通过审查。
- **推断强度**：普通 `train_test_split` 也可能用于实体编号等输入，单凭函数名不能确认记录级划分或泄漏。部分规则和预设答案把这一线索表述为明确矛盾。
- **计划与执行混用**：重复运行、基线与指标规则没有始终要求执行侧证据，计划中的承诺可能让对应检查不再提示缺口。
- **模型引用**：深度复核只检查引用是否出现在任意材料中，未绑定所声明的文件；校验失败时会清除引用而保留发现与建议，无引用输出也可能保留。逐字匹配不等于推断有效。
- **复查入口**：已确认的事实卡片不再提供拒绝/纠正按钮，前端难以废弃旧事实；重新进入报告页又会生成报告，可能改变复查基准。
- **恢复与版本**：已有会话恢复，但尚无材料替换和版本失效机制；存储损坏与写入失败缺少用户可见提示。
- **文件读取**：无 DOCX/XLSX/OCR 解析，未知二进制格式按 UTF-8 替换字符解码；上传端未限制体积或类型。
- **公开服务**：无认证和会话归属控制，不能直接开放多人提交私密研究材料。模型调用和数据写入也需要增加限额与错误反馈。
- **字符位置**：Python 字符索引与 JavaScript UTF-16 索引对 emoji 等字符不同，前端高亮可能偏移。

这些问题不妨碍把现有源码作为独立项目保存，但需要在后续产品完善和正式部署前逐项处理。

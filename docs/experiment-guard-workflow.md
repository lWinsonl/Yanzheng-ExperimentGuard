# 研证：当前工作流程与能力边界

## 当前可运行的流程

1. **确定比较问题。** 学生选择“数据与模型实验”或“算法与系统性能实验”，写出可检验的研究主张。研究主张和计划是生成报告的必填项。
2. **提供计划与执行材料。** 可以直接填写文本，或在“上传实验材料”中选择材料属于“实验计划”还是“执行材料”。浏览器在本机提取文件文字，显示材料预览，并把文字追加到相应文本框。PDF 最多读取前 30 页，单个文件最多 10 MB，文字最多保留前 4 万字。扫描页、图片和图表没有被理解。草稿保存在本浏览器的 localStorage。
3. **确认关键实验条件。** 用户按实验类型手动选择划分单位、重复对象、预处理、调参机会，或运行环境、负载、重复次数。上传文件不会自动替用户填写这些选项。
4. **按规则审查。** 本地规则引擎读取文本框和结构化选项，检查主张是否有比较对象、计划是否过于简略、计划与执行条件是否冲突，以及数据泄漏、公平比较、重复运行等有限情形。结果区分“明确矛盾”“潜在风险”“信息不足”，每条给出触发依据、可能影响、下一步和必要时的待确认问题。
5. **修改并复查。** 用户修改上方材料或条件，写明修改理由，再运行审查。系统记录本轮不再触发的疑点；“不再触发”只表示当前输入不满足该规则，不证明实验已经修好。
6. **独立判断练习。** 报告末尾给一个新的实验情境，让学生先写自己的核查思路，再查看参考思路。开放回答由学生和教师判断，系统不自动评分。

## 目前还不是完整的文献或实验审查智能体

- 上传材料的主要作用是补充文字输入。系统不会对整篇论文进行语义理解，也不能自动确认填写的选项与文件内容一致。
- 规则只覆盖页面列出的检查项；未触发疑点不等于实验有效。当前没有逐页、逐行的证据引用，也没有外部文献检索。
- 文件文字保存在浏览器草稿中，使用共享电脑时应清空草稿。用户应先删除姓名、密钥和不便公开的数据。

## 下一阶段应先补齐的闭环

材料解析 → 带原文位置的事实抽取 → 用户确认抽取结果 → 主张与证据对照审查 → 给出可执行修改建议 → 修改后复查。每个结论应标明“来自哪段材料、仍缺什么证据、是事实冲突还是待核查风险”。再用预先设计的真实漏洞案例测漏报和误报，不能只凭演示效果声称审查准确。

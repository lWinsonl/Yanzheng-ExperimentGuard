# 证据核对与修改验证怎么用

第四步“程序核对结果”展示完整已确认记录的计算；模型复核另列候选解释和待验证建议。来源绑定通过只表示能定位原文，不证明模型推理正确。未采纳输出不显示修改实验操作。

## 实体隔离

上传真实执行产生的entities.json，确认完整记录。除训练/测试编号外，可声明实验范围：

```json
{
  "evaluation_scope": "数据版本与来源:原始图片单位:未见原图任务v1",
  "train_entity_ids": [],
  "test_entity_ids": []
}
```

编号须填真实非空列表；空模板不能证明隔离。evaluation_scope应描述同一数据来源、实体单位和目标，不能为了通过任意填写。字符串相同仍是上传者声明，不是来源认证。

修改后在收集材料页替换旧执行记录、确认新事实，再到第五步运行版本差异复审。“修改后的实际验证”会重查旧失败项：

| 显示 | 含义 |
| --- | --- |
| 问题仍在 | 新记录仍有交集等原检查失败；减半复制不等于解决 |
| 新记录通过本项验证 | 前后一致的声明范围内，提供记录通过此项；不验证整个实验 |
| 当前通过，实验范围待确认 | 新记录交集0，但缺少一致范围声明，不能声称原实验已修复 |
| 尚未验证 | 材料删除、缺新记录、范围改变或不能唯一匹配 |

目前按检查类型、角色、文件名等匹配，保守处理歧义；旧版报告没有程序检查快照时，需要重新审查建立基准。系统不执行上传的任意代码，不通过口头“已经修改”验证结果。

## 二分类召回率

当前接受严格CSV：表头Observed,Predicted0,Predicted1（也接受Observed,0,1），两行Observed必须恰好为0与1，计数为非负整数。行为实际标签、列为预测标签，正类明确为1。系统不猜测转置或标签语义。

确认完整矩阵后，涉及recall/召回率的主张会检查TP+FN。分母为0时显示不可估计，不写成0或100%。需要新评估时应符合原任务抽样规则并说明范围；不能改标签或挑样本使指标可计算。DOCX/XLSX中的任意布局目前不自动解释成混淆矩阵。

## 模型复核

模型只能选择本轮目录里的证据ID，文件、字符区间、程序检查编号由服务器绑定。模型不能把已通过的同一程序检查变成失败；无依据输出放到待核实区。复核期间材料变化会使旧输出失效。

已知计算失败使用固定的操作和验证约束；其他语义建议可能没有程序验证项，须人工核对。长材料提供选中片段，页面标明实际区间覆盖；未提供内容不当作已阅读。

## 实测与仍有的问题

[真实回放报告](../evaluation/reports/grounded-case-replay-2026-11-02/summary.md)保留两次实现修订、12次供应商调用与真实编号验证。当前改善的是证据绑定、结果传递与修复门槛；复杂目标编码仍有漏检，模型也会把一般提醒写为风险。不能据此宣称通用科研审查已可靠或教学效果已验证。

# 材料准备与模型调用故障

## 第二步的判断边界

- 第二步只负责上传、替换及列出材料，上传结果已显示提取的待确认事实数。
- 移除重复的“材料已收到，等待核对事实”卡和独立的空材料准备卡，不自动请求材料缺口分析。
- 上传后直接进入第三步确认事实；没有材料时不能进入事实确认。
- 后端缺口分析接口保留空材料和未确认事实的保护，供需要时独立调用；不会把未确认信息当成缺失。

## 模型失败不能等同于健康检查失败

`/api/health` 仅表示应用运行。复核结果另外携带请求型号、响应型号及安全的失败分类。
超时、连接错误、供应商繁忙、调用频率限制、账号额度、密钥错误和输出截断分别提示；不向页面返回密钥、材料正文或供应商原始错误正文。

诊断数据按调用上下文隔离，不使用全局“最后一次错误”，避免不同学生的并发调用互相覆盖。
思考模式和输出预算配置见 `backend/.env.example`。

## 备用模型

智谱标准端点的 `glm-4.7-flash` 可在失败后手动尝试旧 `glm-4-flash`；也可由管理员设置 `LLM_FALLBACK_MODEL`。
只有点击备用按钮才发出请求；每次尝试仍计入演示额度。成功与失败都会明确标记本次请求型号。
不会修改全局主模型，不接受客户端指定任意模型；备用输出使用相同的证据绑定与建议验证。
备用成功只说明该次请求可用，不表示审查质量更高。

## 2026-11-03 的有限连通性观察

使用本地配置的同一智谱标准 API Key，分别向 `glm-4.7-flash` 和 `glm-4-flash` 各发送一次相同短 JSON 请求。
每次最多 256 输出 tokens，网络超时参数 25 秒，无自动重试，不上传项目材料；新型号显式关闭思考。

- `glm-4.7-flash`：读取超时，约 26.08 秒，没有收到有效正文。
- `glm-4-flash`：SSL 连接提前结束，约 21.97 秒，没有收到有效正文。

这两次观察不能估计长期成功率，也不能代替 Render 环境的验证；不能据此断言换回旧模型会解决问题。
前次新型号曾返回 `429 / 1305`。按[智谱官方错误码](https://docs.bigmodel.cn/cn/api/api-code)，1305 表示模型访问量过大；它与账号欠费、密钥错误、读取超时应分别处理。

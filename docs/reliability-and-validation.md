# 研证：判断边界与验证方法

这版优先核对“证据能否支持推断”，并让补充回答进入可追溯的确认流程。

## 当前工作流

1. 学生填写主张，分别上传计划与执行材料。
2. 规则与模型提取候选事实，学生核对原文后确认、纠正或拒绝。
3. 查看发现，优先补充影响较大的证据。追问排序是手工因子的启发式估计，尚未校准为真实概率。
4. 追问回答保存为独立材料，保留原文锚点；提取的事实必须再经裁决，才能重新审查。
5. 补充说明标为 `followup_answer`，不能自动代替独立的运行证明。
6. 修改后运行版本对比。首次报告作为基准；普通重新审查不会覆盖基准，完成一次版本对比后才推进基准。
7. 复查后做一道新情境练习。有效模型输出提供参考反馈；模型不可用、失败或分数无效时只提供自查建议。

## 三类容易混淆的判断

| 输入 | 当前判断 | 不能推断什么 |
| --- | --- | --- |
| 指标名称、基线名称 | 有相关线索，比较关系未知 | 不能推出主方法更优或比较公平 |
| `train_test_split(device_ids, ...)` | 需核实输入与实际编号 | 不能仅凭函数名断定记录级泄漏 |
| `GroupShuffleSplit(...)` | 有分组意图或实现线索 | 不能证明实际分组输入正确、运行成功 |
| 计划重复五次、设置 `n_runs` 或 seed | 计划或配置线索 | 不能替代观测波动数据 |
| 多次运行结果 | 可核对的波动线索 | 不能自动证明“更稳定”或排除偶然性 |
| 提供的实体编号列表无交集 | 仅支持所提供列表的实体隔离 | 不验证列表来源、完整性及其他泄漏途径 |

当前可对完整、经确认的执行 JSON/CSV/明确列名表格核对限定点估计和样本标准差。要求方法、主张指标、指标方向、条件声明及结论范围相符；NaN、不同条件、未知指标或过宽结论保留未知。格式见[数值材料说明](numeric-results.md)。这不等于已独立核实全部公平性前提、记录真伪、显著性或总体优势。

DOCX 正文/表格与 XLSX 单元格现有只读解析。公式不执行、不采纳缓存结果；图片、图表等未覆盖部分提示缺口。未知格式、非法角色、伪装文本的二进制文件明确拒绝，替换解析失败不清除原材料。

每次报告保存完整事实、主张和材料来源快照。版本配对不以可变证据类别作为身份；歧义、旧快照缺失、撤回证据、主张删除或规则失败时不能自动解除。理由对照只说明类别层面的变化，不证明修改方向正确。

### 实体编号核对材料

上传实际划分产生的完整编号记录，选择“执行材料”，例如 `entities.json`：

```json
{
  "train_entity_ids": ["设备A", "设备B"],
  "test_entity_ids": ["设备C"]
}
```

两侧均须为非空字符串或整数列表。空列表、布尔值、缺失字段不参与自动核对。程序以字符串形式统一编号，因此整数 `1` 与字符串 `"1"` 视为同一编号。用户纠正解释文字或在回答框中声明列表，不会替代上传的原始记录。

## 练习反馈的限制

深度复核的新证据编号协议、计算结果和修改验证见[使用说明](grounded-review.md)；[真实回放](../evaluation/reports/grounded-case-replay-2026-11-02/summary.md)保留两次实现修订和12次真实请求。无效输出不再继续展示修改操作；完整记录检查通过仍不能证明整个研究或语义推断正确。

- 无有效模型评分时，各维分数与总分返回 `null`，`score_status=feedback_only`；前端不显示通过、未通过或已掌握。
- 模型各维分数必须为有限的 0–1 数值，不能用字符串、布尔值、NaN、越界值凑成分数。
- `model_feedback` 仅表示模型返回了格式有效的参考评价；不意味着内容已由教师核验。
- 旧启发式分数不计入新的有效评分统计。统计中的阈值比例也不能解释为学习掌握率。

## 演示版访问与资源限制

会话绑定创建时的浏览器 HttpOnly Cookie，其他浏览器无法枚举或读取材料。它是浏览器持有凭证，不是实名账号或班级系统。清除 Cookie、换浏览器或凭证到期后，无法访问原会话；旧版本没有归属记录的会话不再公开读取。

- 每浏览器最多 20 个会话；单文件最多 5 MB，粘贴材料最多 100,000 字符，单条回答最多 20,000 字符。
- 每浏览器每小时最多 120 次写操作，全进程最多 600 次。
- 模型服务每浏览器每小时最多 60 次实际调用尝试，全进程最多 240 次，重试也计数。
- 配额是单进程内存计数，重启后重置，不是供应商账单硬预算。仍建议在供应商侧设置消费限额。
- Render 免费实例重启或重新部署后仍可能丢失本地会话；本次改动未增加持久数据库。
- 替换成功后才移除当前材料；历史原文保留用于报告溯源，不再进入当前事实审查。

## 如何验证

`backend/tests/test_reliability_workflow.py` 覆盖弱证据、确认、评分、隔离与溯源。`backend/system_tests/test_grounded_review.py` 补充证据绑定、长记录计算、零分母、修改验证和运行中材料变化。离线测试关闭模型；三种宽度的Playwright使用本机临时后端。最新为[196项测试与12项浏览器通过](../evaluation/reports/2026-11-02-grounded/summary.md)，真实模型回放单独报告。

这些是开发者编写的合成回归案例，**不能据此报告真实科研材料上的准确率，也不能据此证明教学效果**。

### 比赛前仍需完成的比较

收集经许可、去标识化的真实课程项目材料，按照“问题明确存在 / 信息不足 / 正确但容易误判”分组。先由指导教师独立给出问题位置、依据和严重度，再评测以下两种条件：

| 条件 | 固定条件 | 比较指标 |
| --- | --- | --- |
| 直接调用同一个模型 | 同一批材料、同一模型版本、可比的调用预算 | 正确发现、误报、引用定位、建议可执行性 |
| 研证完整流程 | 增加事实确认、追问与修改复查，记录额外耗时 | 同上，另记录追问完成率、总操作成本 |

教师标签须在看到系统输出前确定，开发用材料与最终评测材料分开。记录模型版本、提示词、输入截断和调用失败，避免只挑演示成功的样本。

教学评估另做：先记录学生独立判断，再进行辅助修改，最后安排新的同类方法情境，由不知道分组情况的教师评分。应记录提示使用和是否看过参考答案，并安排后续测试；一次模型评分不足以证明迁移学习发生。
